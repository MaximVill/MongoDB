# Football Statistics App (Приложение для футбольной статистики)

Веб-приложение для сбора, хранения и анализа футбольной статистики на основе NoSQL СУБД MongoDB. Проект выполнен в рамках курсовой работы по дисциплине «Базы данных» (2 курс, КемГУ).

Прототип представляет собой Single Page Application (SPA), позволяющее управлять карточками игроков, протоколами матчей, рассчитывать агрегированную статистику в реальном времени и модерировать комментарии пользователей.

---

## Технологический стек

* **База данных:** MongoDB 7.0 (используется официальный нативный драйвер `mongodb` версии 6.x)
* **Бэкенд:** Node.js 20 LTS, фреймворк Express 4.x
* **Фронтенд:** HTML5, CSS3, Vanilla JavaScript (без сторонних библиотек и фреймворков)

## Быстрый запуск

Для локального запуска приложения необходимо выполнить следующие шаги:

### 1. Инициализация и наполнение базы данных
Убедитесь, что у вас запущена локальная служба MongoDB. Наполните базу данных `football_db` тестовыми данными (включает 6 игроков, 6 матчей, 6 пользователей с разными ролями):
```bash
mongosh football_db data.js
```

### 2. Установка зависимостей проекта
```bash
npm install
```

### 3. Запуск веб-сервера
```bash
node server.js
```

После успешного запуска приложение будет доступно в браузере по адресу: [http://localhost:3000](http://localhost:3000)

## Основной функционал прототипа

1. **Дашборд (Главная):** вывод сводных статистических карточек (общее число игроков, матчей, пользователей и голов) и аналитических виджетов (топ-5 бомбардиров и диаграмма забитых голов по командам в реальном времени).
2. **Игроки:** поиск футболистов по имени с использованием регулярных выражений, фильтрация по позиции, просмотр подробной карточки и инкремент голов с помощью оператора `$inc`.
3. **Матчи:** вывод списка всех сыгранных матчей с фильтрацией по турниру и форма добавления нового матча (с записью документа в коллекцию `matches`).
4. **Административная панель:** управление правами пользователей (блокировка аккаунтов через `$set`) и модерация нежелательных комментариев с использованием позиционного оператора `$` в MongoDB.
5. **Централизованная обработка ошибок:** все асинхронные операции бэкенда обернуты в middleware-обертку, возвращающую стандартизированные ответы с кодом `500` в случае сбоев БД.
